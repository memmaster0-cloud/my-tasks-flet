# Мои задачи — Android-приложение на Python/Flet + Supabase

Учебный проект по заданию «Разработка простого Android-приложения на Python/Flet с облачной базой данных Supabase и автоматической сборкой APK через GitHub Actions».

## 1. Что реализовано

- Python + Flet — клиентское приложение.
- Supabase/PostgreSQL — хранение задач.
- `supabase-py` — прямой доступ клиента к таблице.
- CRUD:
  - Create — добавить задачу;
  - Read — загрузить список;
  - Update — отметить задачу выполненной;
  - Delete — удалить задачу.
- GitHub Actions — автоматическая сборка APK.
- RLS-политики для таблицы `tasks`.
- Секреты не хранятся в Git.

## 2. Структура

## 3. Создание Supabase

1. Создать проект в Supabase.
2. Открыть SQL Editor.
3. Выполнить содержимое `supabase.sql`.
4. Проверить, что таблица `tasks` появилась в `public`.
5. В настройках проекта взять:
   - Project URL;
   - anon/public key.

RLS включён в SQL. Для учебного приложения политики разрешают CRUD роли `anon`. Это допустимо только как учебный вариант; в реальном приложении права нужно ограничивать авторизацией и пользователями.

## 4. Локальный запуск

Требуется Python 3.10+.

### Windows PowerShell

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Открыть `.env` и заменить значения:

```text
SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
SUPABASE_KEY=YOUR_SUPABASE_ANON_KEY
```

Затем:

```powershell
flet run main.py
```

Можно также запускать:

```powershell
python main.py
```

## 5. GitHub Secrets

В репозитории открыть:

`Settings -> Secrets and variables -> Actions -> New repository secret`

Создать два секрета:

- `SUPABASE_URL`
- `SUPABASE_KEY`

Не добавлять реальные значения в `main.py`, `README.md`, `.env` или другие отслеживаемые Git-файлы.

## 6. Сборка APK

После push в `main`/`master` GitHub Actions запускает `.github/workflows/build.yml`.

Также workflow можно запустить вручную через:

`Actions -> Build Android APK -> Run workflow`

После успешной сборки открыть выполненный workflow и скачать artifact `android-apk`.

## 7. Проверка

Минимальный сценарий защиты:

1. Запустить приложение.
2. Добавить «Купить тетрадь».
3. Убедиться, что запись появилась.
4. Перезапустить/обновить список и убедиться, что запись хранится в Supabase.
5. Отметить задачу выполненной.
6. Удалить задачу.
7. Установить APK на Android и повторить эти действия.

## 9. Проблемы и решения для отчёта

### Проблема 1. Supabase возвращает пустой результат

Вероятная причина — RLS или отсутствие политики SELECT.

**Проверка:** открыть SQL Editor и убедиться, что RLS включён и существует политика `tasks_select_anon`.

### Проблема 2. Локальное приложение не подключается

Проверить наличие `.env`, названия переменных `SUPABASE_URL` и `SUPABASE_KEY`, а также отсутствие пробелов/кавычек в значениях.

### Проблема 3. GitHub Actions падает на сборке

Сначала смотреть конкретный шаг и полный лог. Затем проверить версию Python/Flet и параметры workflow. Не переписывать весь проект без анализа ошибки.

## 11. Ограничение учебной схемы безопасности

В этом учебном варианте используется `anon` без авторизации, а RLS разрешает CRUD всем клиентам, имеющим публичный anon-ключ. Это сделано для соответствия упрощённому сценарию задания. Для реального приложения такую модель доступа применять нельзя без дополнительных ограничений.
