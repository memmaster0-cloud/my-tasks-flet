# Отчёт по проекту «Мои задачи»

## 1. Цель работы

Разработать минимальное Android-приложение на Python/Flet, подключённое напрямую к Supabase через `supabase-py`, и настроить автоматическую сборку APK средствами GitHub Actions.

## 2. Выбранная тема

**Список задач.**

Пользователь может:
- добавить задачу;
- посмотреть список;
- отметить задачу выполненной;
- удалить задачу.

## 3. Архитектура

```text
Android / Desktop
       |
       v
Python + Flet
       |
       | supabase-py
       v
Supabase
       |
       v
PostgreSQL: public.tasks

GitHub
   |
   v
GitHub Actions
   |
   v
APK artifact
```

## 4. Схема таблицы

| Поле | Тип | Назначение |
|---|---|---|
| id | bigint | уникальный идентификатор |
| title | text | текст задачи |
| done | boolean | выполнена ли задача |
| created_at | timestamptz | дата создания |

## 5. CRUD

**Create:** `insert()` — добавление задачи.

**Read:** `select()` — загрузка списка.

**Update:** `update()` — изменение `done`.

**Delete:** `delete()` — удаление задачи.

## 6. RLS

RLS включён для `public.tasks`. Для учебного сценария созданы политики SELECT, INSERT, UPDATE и DELETE для роли `anon`.

## 7. CI/CD

Workflow находится в:

`.github/workflows/build.yml`

Он:
1. получает код из GitHub;
2. запускает официальный Flet Build Action;
3. собирает APK;
4. публикует APK как artifact.

## 8. Скриншоты

Перед сдачей вставить реальные скриншоты:

1. **Supabase:** таблица `tasks`.
2. **Supabase:** RLS Policies.
3. **VS Code:** исходный код.
4. **Запущенное приложение:** список задач.
5. **GitHub Actions:** успешный зелёный workflow.
6. **Artifact:** скачивание APK.
7. **Android:** установленное приложение.
8. **Android:** задача добавлена/выполнена/удалена.

## 9. Разбор проблем

### Проблема 1 — RLS

Если SELECT/INSERT не работает, проверяются политики RLS и имя таблицы.

### Проблема 2 — секреты

Ключи нельзя хранить в Git. Локально используются переменные окружения, а в GitHub — Secrets.

### Проблема 3 — CI/CD

При ошибке сборки анализируется конкретный шаг Actions и версия инструментов, после чего выполняется минимальное изменение.

## 10. Вывод

В результате создан учебный проект, объединяющий Python, Flet, Supabase/PostgreSQL, GitHub и GitHub Actions. Приложение выполняет CRUD-операции с облачной таблицей, а APK собирается автоматически в CI.
